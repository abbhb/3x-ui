# 远程节点的原生出站、路由和用户 IPv6

## 配置只有一份

- 原生“出站”“路由”和 Xray 配置页共用服务选择。`nodeId=0` 管理新面板本机；正整数管理对应启用节点。
- 读取、保存、出站测试、用量、订阅出站、地理规则和第三方出站集成均调用所选服务的原生接口。
- 主控不复制节点模板到自己的设置表。节点验证、持久化及热应用仍走原生服务；停止的核心保持停止。
- 原生页面的缓存按节点隔离。切换服务需明确丢弃未保存编辑；请求失败不会退回本机配置。
- 主机详情提供对应服务的原生出站与路由链接。IPv6 出口摘要直接读取原生绑定与用户规则，不再展示旧控制器快照、迁移分类或提供第二套策略写接口。

API 使用相同的 `/panel/api/xray/*` 路径，通过查询参数 `nodeId` 选择服务。
远程节点必须升级到支持这些接口及权限的版本，并在原生节点设置中提供 **node-admin** 令牌。
node-sync 不增加配置权限；node-admin 只管理被调用服务本机，不能再通过它转调该服务下的其他节点。
停用节点立即拒绝访问；部署与接管必须先准备并验证对应的原生节点，不能靠启用旧占位记录冒充已交付。

## 从面板设置用户 IPv6

1. 在原生“出站”选择目标服务，打开“按用户 IPv6”。
2. 首次配置该服务真实拥有、已经由服务商路由的 IPv6 `/64` 和网卡。没有可用前缀的服务继续使用原有出站。
3. 选择一个入站及其已授权客户端。分配器以该服务原生 Client ID 保留稳定 `/128`，在网卡上准备并回读地址。
4. 辅助编辑器把普通 `freedom` 出站及 `user + inboundTag + ip: ::/0` 路由加入当前原生草稿。检查后点击页面“保存”应用。
5. 若该入站所有用户都应有固定出口，勾选“此入站所有已授权用户及后续新增用户自动分配固定 IPv6”。它写入可见的普通原生路由；后续新增的原生客户端在原生配置协调时分配地址并插入用户规则。
6. 后续直接使用原生出站、路由表单修改或删除；没有第二份策略存储或独立后台控制器。自动模式下保留标签 `user6-<Client ID>-<入站>` 的规则会随客户端改名同步其单用户身份，其他字段、禁用状态与出站改名保留。改为完全手工维护时先停止自动纳入。

原生出站的 `sendThrough` 显示分配地址，原生路由显示用户与出站对应关系。
路由域名策略设为 `IPOnDemand`，IPv6 出站使用 `ForceIPv6` 解析；双栈域名的 IPv6 分支可以匹配固定地址出站。
IPv4 字面目标与仅有 A 记录的域名不匹配该 IPv6 路由，继续执行原路由。
这不提供“某个 IPv6 目标连接失败后跨出站重试 IPv4”的保证；也不把固定 IPv6 接入地址改成用户地址。
此前的规则继续优先，所以封禁、域名分流等不会被插入的用户规则越过。

辅助编辑器只处理最终落到普通直连出站的入站。已有源地址绑定、WireGuard、重定向、路由脚本或复杂出口需要明确编辑原生路由，
不会自动改成 IPv6 直出。重复生成同名出站会被拒绝，原生表单中的手工修改不会被静默覆盖。
存在运行时注入的订阅出站时，须先明确该入站的原生直连路由，不能根据模板第一个出站推断真实默认出口。

自动模式在用户规则之后、原直连兜底之前插入 `user6-pending-<入站>`（IPv6 黑洞）与 `user6-auto-<入站>`（直连兜底）。IPv4 保持原路由；地址尚未准备的新用户不会短暂共享 IPv6。删除或禁用自动规则可停止自动纳入，辅助按钮会同时移除 pending 规则并保留所有已有用户绑定。所有这些对象都能在原生“路由”中检查。

## 地址准备与生命周期

`nativeIPv6Pool` 是本机地址池设置，`NativeIPv6Lease` 仅保存 Client ID 与地址的对应关系。
代理凭据、授权、限额、入站、出站和路由分别仍以原生 Client / ClientInbound / Inbound / Xray 模板为准。
凭据轮换、客户端改名或地址准备失败后重试不会更换已有租约。

主机操作仅执行 `ip -6 address add <租约>/128 dev <网卡> preferred_lft 0 noprefixroute`，检查重复地址检测及准备状态。
租约保持有效，但不作为系统自动源地址选择的首选；原生 `sendThrough` 显式绑定仍可使用。
这样未选择按用户出口的连接、共享出站及同机其他服务继续使用原来的系统源地址选择。
没有 shell 拼接，不创建路由表、mark、NAT、监听器或第二个 Xray 启动器，也不读取或修改旧 HY2 分配库。
需要 Linux、iproute2 和相应网卡管理权限。内核拒绝或地址尚未准备时明确失败，租约保留为待准备供重试。
保存或重启原生服务时，只恢复该服务原生模板实际引用的租约地址。

已有租约时禁止更换网卡或前缀；删除出站、用户或路由不会回收租约，以免地址被其他用户复用。
跨前缀、跨主机或旧 HY2 地址交接须另做显式迁移，不能通过改字段替代。按用户匹配使用原生客户端 email，改名、删除或复用 email 时应同步检查原生用户路由；租约本身仍以 Client ID 稳定持有。

## 验证与证据边界

- 针对性 Go 测试覆盖节点派发、停用服务、令牌隔离、稳定租约、失败重试、地址恢复及主机操作边界。
- 前端测试覆盖服务缓存与写入隔离、原生规则顺序、既有源地址绑定及隧道保护。
- CI 的隔离 netns 用真实 Go 地址分配、实际前端生成函数、原生配置验证与持久化，以及固定版本 Xray 做 48 次连接探测：
  两名用户、IPv4 / 固定 IPv6 接入、TCP / UDP、IPv6 / IPv4 字面目标与双栈 / IPv4 域名；并删除一个测试地址后恢复租约再重启验证。
  另检查租约有效期及第三名未选择用户的 TCP / UDP 共享源地址，在地址准备和恢复后都不被用户租约替换；开启自动纳入后，验证准备期间 IPv6 阻断、IPv4 正常、新用户独立地址及恢复后地址不变。
- 地址已准备、核心运行与实际出口是不同证据。出站测试和连接观测用于核实实际源地址；回读网卡地址不代表远端已观察到该出口。

隔离实验只创建随机命名的测试 namespace 和临时数据库，不使用生产配置。
