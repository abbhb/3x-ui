# 原生功能优先：迁移收敛审查

日期：2026-11-17。审查基于 fork `b1a14ce7`，原生能力对照起点为 `5297fd3c`。
用户验收指出：入站、出站和路由没有在面板形成完整操作链，自定义入口又叠加了一套概念。
后续按原生数据与操作流程收敛；不能把导入成功、线路可用或配置分类当成可管理能力已交付。

## 能力归属与收敛方向

| 能力                           | 原生落点                                     | 最小扩展边界                                                                                                            |
| ------------------------------ | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 用户凭据、入站授权、额度、到期 | Client、ClientInbound 与原生客户端接口       | 门户交易提交到这些原生对象；历史财务快照不是另一份运行配置                                                              |
| 协议、传输、TLS、XHTTP         | 原生 Inbound / Host 及其表单、校验和订阅渲染 | 只补确实缺失的字段或格式转换；不再在商务页面建立同义线路编辑器                                                          |
| 服务器出口                     | 原生出站、`sendThrough`、解析策略、出站测试  | 缺远程节点作用域就扩展原生接口和页面作用域，不新建出口对象                                                              |
| 入站 / 用户到出口的选择        | 原生路由表单及 Xray 路由规则                 | 不用一张可独立编辑的分类表声称已经修改路由                                                                              |
| WireGuard 转发                 | 现有服务的出站、源地址绑定及路由             | 保留现有内核隧道和防漏策略；改用另一种实现前另做协议与出口验收                                                          |
| 客户端订阅混入外部线路         | 原生 ClientExternalLink、订阅解析与渲染      | 公共套餐授权、客户私有归属、加密及持久快照若原生缺少，只补这些差异；不能把客户端订阅误装成服务器出站                    |
| 门户、钱包、账本、MGMA         | 原生没有对应的完整业务模型                   | 保留必要业务扩展，代理配置仍由 Client / Inbound / Host 持有                                                             |
| 用户固定 IPv6                  | 原生出站与用户路由可表达部分固定配置         | 地址分配、网卡地址准备、原分配库延续和运行回读仍需主机能力；先验证能否用原生字段表达，不能默认整套自定义 NAT 都必须保留 |
| 实际拨号和分配状态             | 原生在线统计不等于实际出口证据               | 只补可核实的运行报告，不伪造出口，也不将观察记录当作配置来源                                                            |

上述原生落点可在 `frontend/src/pages/xray`、`internal/web/service/xray_setting.go`、
`internal/sub/external_subscription.go` 及原生 Client / Inbound / Host / Node 模型中核对。
“原生能表达部分配置”不等于生产旧规则可以立即删除；IPv4 回退、用户身份、配额、证书及隧道防漏必须分别验收。

## 本轮落实：删除无效编辑入口

- 服务主机的“线路出口约定”改为只读的“迁移时的出口记录”。已有记录保留，避免丢失交接依据。
- 移除 `POST /panel/api/serviceHosts/line/:id` 与只写分类表的服务方法，停止提供一个不会修改转发的“保存”操作。
- 原生出站、路由、协议配置和真实 IPv6 控制器接口保持原职责。本轮不改任何生产出口，不重启核心。
- 现有“服务主机”保留主机归组、入口关联、控制器状态与连接证据；不再把它扩展成另一套服务器路由管理器。

## 尚未完成的操作链

原生出站和路由页面目前读取面板本机模板。远程 Node 的 API 也没有提供这两页的完整管理作用域；
`node-sync` 权限不能被当成任意远程配置权限。应在现有页面和接口中明确服务选择、权限、读取、校验、应用及生效回读，
复用同一份 Xray 配置。这个缺口不能用新的“线路策略”页面或只写说明字段绕过。

自定义级联 / XHTTP 订阅覆盖的删除由独立变更处理。本轮未合并或覆盖该工作中的代码；
涉及既有订阅参数时，须明确哪些已经由原生表达、哪些不再支持，不能静默改出口或扩大授权。

固定 IPv6 的后续收敛也要明确原生字段和主机组件各自负责什么。
旧 HY2 尚在承载用户连接，旧分配库和 NAT 规则继续保留；不得为了完成界面整理先停掉旧链路。

## 下一轮实现与验收要求

先检查原生实现，再写出最小差异及数据处理方式。验收以用户从面板完成的真实路径为准：

1. 选定服务，打开其原生出站及路由，能看清入站与实际生效出口的对应关系。
2. 保存后校验目标服务配置并回读生效状态；不能只看到数据库字段变了。
3. 对地址族、固定用户地址、IPv4 回退与 WireGuard 防漏分别做实际连接验证。
4. 旧记录、旧令牌权限或尚未接管的服务必须明确显示边界，不能自动冒充已管理。

以上剩余项是后续工作，不代表本轮已经完成远程出站管理或新的用户 IPv6 策略部署。
