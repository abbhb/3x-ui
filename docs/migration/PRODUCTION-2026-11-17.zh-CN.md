## IPv6 接入与出口必须分开理解

美国主机的固定接入 IPv6 为 `2602:f35c:0:169::a`。
P1 / P2 / P3 / P4 名称中的 IPv6 指客户端某一段连接用这个固定地址接入，
不会因此自动开启按用户分配的 IPv6 出口。P3、P4 分别允许上传、下载采用不同的 TLS-CDN / REALITY 连接参数；
P5 有 Cloudflare 双 CDN 和 EdgeOne IPv6 回源两种方案，回源 IPv6 也不是用户出口地址。

目前只有旧 `US03_HY2_IPV6` 入站，即 UDP 22444，保留按永久用户数字 ID 绑定 IPv6 的规则。
同一个用户通过 IPv4 或 IPv6 接入它，身份和分配地址都不应变化；访问 IPv4 字面目标仍可使用共享 IPv4。
普通美国 02 双栈服务的 IPv6 出口是主机地址，不能据此判断用户专属 NAT 已开启。
两条 WireGuard 线路是美国 01 的 IPv4 出口，也不按用户分配美国主机的 IPv6。

未来接管旧 HY2 时，固定 IPv6 接入地址、用户 UUID / HY2 Auth、永久数字 ID、
原分配库及其中已删除用户的预留项都要分别保留。禁止空库重新分配，禁止在旧控制器运行时让新控制器操作相同 namespace、mark 或 nft 表。

## 回退与用户确认后的下一步

单条新线路失败时，先停止对应新服务释放端口，再恢复对应旧容器原 restart policy 并启动，
只恢复该旧节点的控制连接；不得重连服务 4，不得重启旧主面板。旧 HY2 的数据目录可能与旧服务 5 共享，禁止覆盖它。
域名回退只恢复备份的 Nginx 配置，先 `nginx -t` 再 reload。
已产生新用量后，不能用切换前的数据库覆盖活动库；必须保留双向交接回执并先对账。
若需要重新开放旧业务写入，也要先停新业务写入，完成授权与计量交接后再解除旧触发器，防止两边同时售卖或轮换凭据。

**只有用户明确告知“已更新订阅、在本机切到新线路并验证联网”，才开始接管旧服务 4 / 旧主核心。**
先在隔离监听准备原生服务 4，核对固定 IPv6 接入、用户身份和完整分配库，
再按第二阶段合同交接旧控制器、监听和 NAT 所有权；切换过程中不能让两个控制器同时写原分配库。
收尾时等待旧采集器提交最终用量、逐用户核对双方回执，确认旧计量不再增长，
再停交接 timer、备份最终状态、解除交易冻结。仅一次零增量不足以证明旧连接已退出。
本次保留的旧主面板、HY2、控制器和数据尚未达到可删除条件。
