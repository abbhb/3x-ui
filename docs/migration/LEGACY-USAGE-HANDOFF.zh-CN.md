# 旧内核保留期间的流量交接

用户尚未确认本机代理已切换时，旧主面板 Xray 与美国 03 HY2 服务继续运行。新业务与旧业务各自采集自己内核的增量，不能让两个采集器同时重置同一个 Xray 计数器。

`tools/legacy_usage_handoff.py` 是这个过渡窗口的 SQLite 运维工具，不是第二个门户或节点控制器。它不修改认证、额度、到期日、路由、IPv6 地址、NAT 或进程。

适用条件：目标刚完成离线原子导入；保留用户全部使用 `no_reset` / `never`，没有待生效套餐；购买、充值、续期、流量重置、用户创建与凭据轮换已冻结。新旧两边的管理员不能在此窗口修改业务授权。PostgreSQL 不适用此工具。

## 计量方式

冻结时记下源用户当前用量、历史重置累计，以及导入到目标的当前用量。以后每轮：

1. 从源用户累计用量中扣除本工具先前写入的原生用量镜像，得到真正的旧内核累计。
2. 把尚未交接的旧内核增量加到目标 `client_traffics.down`，沿用迁移时“旧总流量作为下载量”的明确策略；同一事务提交交接回执。
3. 从目标当前总量扣除冻结基线和已交接旧流量，得到原生节点累计，再把尚未镜像的部分加到旧用户用量；同一源库事务提交镜像回执。

两个数据库各自记录回执，不依赖跨库原子提交。任一步提交后中断，重跑只补尚未提交的部分；不会把回写源库的原生流量再次当作旧流量。两边都使用原子加法，与面板自己的增量写入串行，不覆盖同时产生的流量。旧面板因此仍按合并用量执行旧节点的额度检查，新面板也能按合并用量限制新节点。

源重置策略变化、目标重置、身份丢失、累计回退、另一交接基线或数据库不可用都会停止同步；不得通过清空回执、修改基线或钳制负差值“修复”。同步器只输出用户数量与本轮总字节，不输出凭据和逐用户记录。回执与源数据库、目标数据库一起备份。

## 初始化与运行

在目标尚未启动时，由冻结副本和已逐记录回读的导入报告生成私有基线文件，目录 `0700`、文件 `0600`：

```json
{
  "schema": "marzban-live-usage-handoff/v1",
  "bundle_sha256": "替换为导入报告中的64位摘要",
  "users": [{
    "source_id": 7,
    "email": "7.替换为冻结的源用户名",
    "source_lifetime": 140,
    "target_usage": 100
  }]
}
```

`source_lifetime` 是冻结时 `users.used_traffic + SUM(user_usage_logs.used_traffic_at_reset)`，`target_usage` 是导入后的 `up + down`。只能使用该冻结副本的值，不能拿初始化时源库又新增的流量替换基线；这些新流量由第一轮交接接收。

```sh
python3 tools/legacy_usage_handoff.py initialize \
  --source /受控源库路径/db.sqlite3 --target /受控目标库路径/x-ui.db \
  --baseline /受控目录/baseline.json --offline-target

python3 tools/legacy_usage_handoff.py sync \
  --source /受控源库路径/db.sqlite3 --target /受控目标库路径/x-ui.db
```

由单个 root 的 systemd oneshot / timer 每 10 秒运行 `sync`，不要并行启动多个同步器。使用已验证的固定路径，设置超时、私有目录与日志权限。初始化会创建 `xui_handoff_*` 元数据表，但不会重置已有进度；目标已经产生计量时拒绝首次初始化。

用户确认切换后，再逐服务停止已授权的旧内核，等待旧采集器提交最后一批用量，执行同步并逐用户回读两边计量。确认旧计量不再增长、目标包含最终旧增量后，停用同步 timer，保留回执和最终快照，再解除交易与业务变更冻结。不能仅凭一次零增量就认定所有旧连接已经退出。

## 验证范围

单元测试覆盖两个提交位置中断重放、提交间新增旧流量、双向增量重复同步、源/目标重置拒绝及基线替换拒绝。生产冻结副本也在独立副本上验证过 5 个用户的双向交接和重放无新增。此证据不等于生产同步 timer 已运行；生产部署记录需要另记最后同步时间、累计回执与受保护进程状态。
