# Mihomo 订阅数值与指纹兼容

2026-11-18 从公网读取的完整订阅包含 169 个节点，其中 38 个外部 XHTTP 节点的 `sc-max-each-post-bytes` 为科学计数法字符串，`sc-min-posts-interval-ms` 为浮点数。Mihomo 1.19.33 和 1.19.34 均把这些字段转为字符串再用 `strconv.Atoi` 解析，因此整份订阅校验失败。原生入站的 XHTTP 导出已有十进制处理，外部快照合并此前未经过该路径。

修复在全部原生节点、外部快照和自定义路由内容合并后的订阅输出处执行：

- 只对上述两个 XHTTP 字段转换精确整数，输出十进制字符串；不截断小数，不修改合法区间，不修改其他字节数、时长或复用参数。
- 精确处理科学计数法字符串，避免大整数经过浮点中转丢失精度；无效、越界或非整数输入保留给内核校验，不伪造成有效配置。
- 移除已废弃的 `global-client-fingerprint`。它在上述内核中打印 error，但单独存在不会令 `-t` 失败。仅为支持该字段的 TLS 节点补充缺失的 `client-fingerprint`，保留节点已有值。
- 同样处理原生内联 proxy-provider 的 payload；远程 provider 仍由原生客户端加载。

不更改保存的外部快照、来源凭据、授权、端口、用户额度或服务端 Xray 配置。每次订阅刷新均执行同一输出处理，无需修改用户客户端脚本。

回归覆盖真实的外部快照导入、加密保存、解密投影、完整订阅导出和 Mihomo 内核 `-t`，包括浮点整数、科学计数法、合法区间、显式指纹优先级及无效值不被取整。CI 的 `tools/subscription_runtime_lab.py` 对生成的完整外部 XHTTP 订阅执行实际内核校验。

## 入站的独立前置节点

在「入站 → 编辑 → 订阅前置」粘贴一个独立的 Mihomo 节点，点击「保存前置」。再次打开页签时，文本框会回填已保存节点的完整 JSON，包含连接凭据，可直接修改单个字段。客户端刷新 Mihomo 订阅后，选择原来的落地条目，流量依次经过客户端、前置、落地。具备该入站订阅权限的客户端也会收到前置的连接凭据。

配置随入站记录加密保存，使用主面板现有的 `XUI_EXTERNAL_SUBSCRIPTION_ENCRYPTION_KEY`。普通入站编辑和节点同步保留前置。管理员可在同一页签更换或移除它。旧版本使用的 `XUI_MIHOMO_INBOUND_DIALERS_FILE` 在升级时按 tag 一次性导入，成功后可以归档旧文件并移除该环境变量。
